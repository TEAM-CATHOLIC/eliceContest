# 서비스 하나로 확인하는 메일 → 탈퇴 안내 → 완료 메일 시연

모아북이라는 가상 서비스와 합성 EML 2통만 사용합니다. 실제 계정·메일함·비밀번호를 사용하거나 실제 데이터를 삭제하지 않습니다. 외부 메일 전송도 없습니다. 실제 로컬 분류기, 기존 파일 파서·분석 파이프라인, 인벤토리·브라우저 안내 화면, 실제 PlaywrightWithdrawAgent를 연결하는 별도 시연 실행점입니다. 일반 앱 실행과 공유 contracts는 바꾸지 않습니다.

## 실행

로컬 ML 환경과 Chrome이 필요합니다. 기존 분류기 문서(CLASSIFIER.md)에 따라 각 PC의 v1 모델 폴더(manifest.json, weights.json, 로컬 E5 캐시)를 준비합니다. 모델과 개인 메일은 저장소에 포함하지 않습니다. v2 실험용 다중 분류 가중치는 현재 실행점과 호환되지 않습니다.

```powershell
uv run --group ml python -m account_cleaner.demo_mail --model-dir 'C:\local-only\classifier-artifacts' --data-dir 'C:\local-only\mail-demo'
```

앱마다 새로운 무작위 폴더와 시연 세션을 만듭니다. 기존 폴더의 완료 메일을 새 실행에 재사용하지 않습니다. 이 파일들은 실제 사용자 데이터와 분리된 합성 시연 자료입니다.

## 사용자 조작

1. **이용 메일 분석**: 가입 완료 합성 EML을 실제 로컬 모델과 보조 문구 기준으로 분석하고 후보 1개를 표시합니다. 첫 실행은 모델 로딩 때문에 시간이 걸립니다.
2. **탈퇴 화면 안내**: 실제 Chrome과 브라우저 에이전트를 시작합니다. Chrome에서 **시연 계정으로 계속**을 누른 뒤 앱의 **직접 처리했어요, 계속**을 누릅니다. 비밀번호처럼 보이는 읽기 전용 `demo` 표시는 기존 인증 넘겨주기 감지용 합성 요소이며 실제 입력·인증정보 저장은 없습니다.
3. 에이전트는 **계정 영구 삭제 (시연용 메일 생성)** 버튼 앞에서 멈춥니다. 이때 앱은 아직 완료가 아닙니다. 해당 버튼을 **사용자가 직접** 누르면 로컬 보관함에 합성 탈퇴 완료 EML이 생성됩니다.
4. 앱이 1초 주기로 시연 보관함의 새 파일을 확인하고, 같은 서비스·진행 시작 이후 날짜·새 메일 ID·명시적인 완료 문장을 확인하면 완료 상태와 **탈퇴 완료 메일 확인 — 모아북 (시연)** 알림을 표시합니다. 이 폴링은 시연 파일 감시이며 실제 Gmail 자동 동기화 기능이 아닙니다.

## 판단과 제한

- `classifier/completion.py`는 완료 **근거**를 반환합니다. 문구 기준이며 별도로 학습한 탈퇴 판정 모델이라고 설명하지 않습니다.
- 과거·이미 읽은·다른 서비스·전달/인용 메일은 제외합니다. 요청 접수, 삭제 예정, 조건문, 구독 해지는 완료로 처리하지 않습니다.
- 발신 주소와 Date 헤더만으로 발신자 진위나 현재 계정 상태를 증명할 수 없습니다. 실제 서비스에 적용하려면 계정 식별·발신 신뢰·메일 동기화 및 진행 기록 연결이 더 필요합니다.
- 합성 완료 메일의 명시적 문장 검출을 보여주는 시연이며 실제 서비스의 탈퇴 성공이나 분류 정확도를 입증하는 자료가 아닙니다.
- 사이트는 루프백에만 열고 Host·Origin·세션 쿠키·일회성 세션 토큰을 확인합니다. 에이전트가 완료 POST를 호출하지 않습니다.
- PR #47의 서비스 식별 모듈을 사용합니다. PR #46의 상태 저장 작업이나 보류 중인 공유 인터페이스 변경을 대신하지 않습니다.
