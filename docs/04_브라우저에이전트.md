# 브라우저 에이전트 — 계정 정리 AI 에이전트

> **원문:** 브라우저 담당 (`browser_agent_mvp`의 번호별 README 22개)
>
> **정리:** 이정훈 — 저장소 구조에 맞춰 한 문서로 합침
>
> **버전:** v1.0
>
> **작성일:** 2026-11-16

설치된 Chrome을 앱 전용 프로필로 띄워 플레이북대로 탈퇴 화면까지 이동한다. 비밀번호·인증·결제 화면에서는 멈추고 사용자에게 넘기며, **최종 탈퇴 버튼은 누르지 않는다** (PRD F-06, 5장).

---

## 2. 실행 흐름

1. 앱 전용 프로필로 Chrome을 띄우고 플레이북의 탈퇴 화면 주소로 이동한다.
2. 로그인이 필요하면 서비스가 로그인 화면으로 돌려보내고, 엔진이 비밀번호 칸을 감지해 **USER_TURN(로그인)** 을 보낸다.
3. 사용자가 Chrome에서 직접 로그인하고 앱에서 '계속'을 누르면 **같은 페이지에서 다음 단계부터** 이어간다.
4. 탈퇴 화면(목표 요소)이 보이면 **REACHED**로 멈춘다. 최종 버튼은 사용자가 누른다.

## 3. 안전 장치

| 장치 | 동작 |
|---|---|
| 전용 프로필 | 사용자의 기존 Chrome 프로필을 쓰지 않음 |
| 도메인 제한 | 플레이북 `domains`(하위 도메인 포함) 밖으로 이동하면 중단. 유사 도메인(`example.com.evil.io`) 차단 |
| 외부 인증 | `auth_domains`(구글·애플 로그인 등)에 들어가면 조작하지 않고 사용자에게 넘김. https만 인정 |
| 최종 버튼 차단 | 클릭할 요소의 셀렉터·글자에 "Delete account", "계정 영구 삭제", "회원 탈퇴" 등이 있으면 클릭하지 않음. 셀렉터 복구로 찾은 요소도 같은 검사를 거침 |
| 사전 검사 | 브라우저를 열기 전에 외부 이동·최종 버튼 클릭 단계가 있는지 검사 |
| 입력값 비보관 | 비밀번호·인증번호를 읽거나 입력하거나 저장하지 않음 |
| 민감정보 가리기 | 이벤트·오류에서 이메일, 6자리 인증번호, 카드번호를 가림 |

### 사용자에게 넘기는 화면

| 감지 | 계약 이유 (`HandoffReason`) |
|---|---|
| 비밀번호 입력칸 | `LOGIN` |
| 일회용 코드 입력칸 (`autocomplete=one-time-code`) | `TWO_FACTOR` |
| 캡차 iframe·요소 | `CAPTCHA` |
| "본인인증", "verify your identity" 문구 | `IDENTITY` |
| 카드번호 입력칸, 결제 iframe | `PAYMENT` |
| `auth_domains` 주소 | `EXTERNAL_AUTH` |

## 4. 플레이북 작성

계약 형식(`contracts.Playbook`)으로 쓰고, 엔진이 실행할 단계는 `steps`에 넣는다.

```json
{
  "schema_version": 1,
  "id": "github",
  "service": "GitHub",
  "domains": ["github.com"],
  "login_methods": ["email"],
  "login_url": "https://github.com/login",
  "password_reset_url": "https://github.com/password_reset",
  "withdraw_url": "https://github.com/settings/admin",
  "steps": [
    {"action": "wait_for", "value": "main", "description": "계정 설정 화면 로딩 대기"},
    {
      "action": "reach_target",
      "value": "text=/Delete account/i",
      "fallback_texts": ["Delete account"],
      "description": "계정 삭제 구역 확인 (최종 클릭 전 정지)"
    }
  ]
}
```

| `action` | 동작 |
|---|---|
| `navigate` | 허용 도메인 안의 주소로 이동 |
| `click` | 요소 클릭 (최종 탈퇴 문구면 차단). `"menu": true`이면 아래 참고 |
| `wait_for` | 요소가 보일 때까지 대기 |
| `reach_target` | 목표 요소가 보이면 REACHED로 멈춤 — 마지막 단계여야 함 |

- `fallback_texts`: 셀렉터가 깨지면 이 글자로 다시 찾는다 (UI가 조금 바뀌어도 동작).
- `description`: 앱의 단계 표시(Step n of m)에 그대로 보인다.
- `menu`: 탈퇴 화면으로 **가는** 메뉴 링크 표시 (예: 한국 사이트의 "회원탈퇴" 메뉴). 글자가 최종 문구여도 **링크(`<a>`, role=link)일 때만** 클릭한다. 버튼이면 최종 버튼일 수 있어 그대로 차단한다. 사전 검사는 오류 대신 확인 경고를 남긴다.
- 주소는 https만. 예외로 이 기기 안 주소(127.0.0.1, localhost)는 http도 허용하며, 배포 환경에서는 `ACCOUNT_CLEANER_ALLOW_LOCAL_HTTP=0`으로 끈다.

## 5. 로컬 데모 (실제 계정 없이)

실제 서비스 화면 변경이나 계정 상태에 흔들리지 않고 핵심 흐름(넘겨주기 → 재개 → 최종 버튼 앞 정지)을 보여 준다. 데모 사이트는 이 기기 안에서만 열리고 삭제 기능이 없다.

```bash
cd app
uv run python -m account_cleaner.browser.demo
```

1. Chrome이 열리고 로그인 화면에서 멈춘다 (터미널에 `user_turn`).
2. Chrome에서 아무 비밀번호나 넣고 로그인한다.
3. 터미널에서 Enter → "계정 영구 삭제" 버튼 앞에서 `reached`로 끝난다.

자동 테스트 `tests/test_browser_demo_e2e.py`가 같은 흐름을 실제 Chrome(headless)으로 CI에서 확인한다.

## 6. 발표 전략 (브라우저 담당 제안)

**한 문장:** 메일은 기기 밖으로 보내지 않고, 사용자의 기존 브라우저도 건드리지 않으며, AI는 탈퇴 직전까지만 안내한다.

**3분 시연**
1. 데스크톱 앱에서 후보를 고른다.
2. 전용 Chrome 프로필이 열린다.
3. 비밀번호 화면에서 에이전트가 스스로 멈춘다 ← 강조
4. 사용자가 직접 인증하고 '계속'을 누른다.
5. 탈퇴 직전 화면에 도착하지만 최종 버튼은 누르지 않는다 ← 강조
6. 실행 시간, 넘겨주기 횟수, 정책 차단 수를 결과로 보여 준다.

**심사 포인트**
- 문제성: 잊힌 계정과 개인정보 유출 위험
- 기술성: 영구 프로필, 상태 머신, 셀렉터 복구
- 안전성: 사용자 넘겨주기, 도메인 제한, 최종 클릭 차단
- 완성도: 실제 Chrome 테스트, 서비스 플레이북, 로컬 안정 데모
- 확장성: JSON 플레이북만 추가하면 서비스 확장

**숨기지 말 제한:** 실서비스 UI는 바뀔 수 있다. 플레이북 사전 검사와 셀렉터 복구로 어떻게 관리하는지 함께 보여 준다.

**시연 전 점검:** Chrome 설치 확인 → `uv run pytest` 통과 → 대표 서비스 플레이북 사전 검사 100점 → 실서비스가 안 되면 로컬 데모로 핵심 흐름부터 시연.

## 7. 남은 과제

| 과제 | 비고 |
|---|---|
| 대표 3곳 실제 테스트 계정으로 시연 | 논의사항 D-01 |
| LLM 폴백 | 마스킹 정책(D-06) 확정 후 |
| 탈퇴 전 조건(구독·잔액) 자동 요약, 플레이북 서명·자동 업데이트 | 정식 출시 단계 |
